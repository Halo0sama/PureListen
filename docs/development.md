## 本轮改进

### 网络与登录

新增共用 `NetworkMode` 与 `CurlTransport`。国内服务默认直接连接，API 与下载均忽略应用层系统代理及终端代理环境变量。只有用户手动选择「跟随系统代理」才读取系统 HTTP(S)/SOCKS 或终端代理；下载会话与 API 使用同一模式。API 的 PAC 自动代理暂不支持，会返回说明性错误。

curl 失败退出、HTTP 错误和超时不再伪装成空 JSON；取消任务会终止对应进程。短链展开复用同一传输层，不再同步等待进程阻塞调用线程。临时请求文件放在权限 `0700` 的独立目录并在完成或失败后清理。

修复网易云和 B站通用 API 的响应头分行：Swift `String.split(separator: "\n")` 无法按预期拆开 CRLF 字符簇，导致 `Set-Cookie` 漏读；现在使用 Foundation 的换行分隔，保留 Version=1 以及值中带等号的 Cookie。网易 Cookie 读取增加互斥保护，日志移除生产路径的完整登录响应头与 B站跨域票据地址。

### 下载与缓存

改用 `URLSession.download(for:delegate:)` 将文件下载到磁盘，并报告真实传输进度。缓存名称包含完整 URL、调用方 key、请求头与格式的 SHA-256 标识，避免不同站点或账号的同名音源串用。签名 URL 更新会建立另一份缓存。

只有 HTTP 200、大小合理且不是 HTML/JSON/XML 错误页的响应才提交为缓存。提交失败会抛出错误；并发下载同一资源时可以复用另一请求已提交的完整文件。旧版缓存保留，仍可通过设置页清除。

### 播放与输入

播放解析、下载及歌词请求记录请求身份；切歌、取消等待、登出或退出应用会取消旧任务。即使旧请求忽略取消并延迟返回，也不能改写新播放。开始新请求前停止旧播放，避免界面显示下载而旧曲仍在输出。

B站的上下曲及自然播完现在沿当前分 P 队列移动，结束时释放播放。单独传入的条目自动建立单项队列。手动换设备时保留 B站/直链来源，先停止旧设备再更换目标 ID。

修复 BV/av 正则提取，支持分享文案中的链接、网易 `/#/song?id=` 与 B站 `?p=`。站点匹配使用真实 hostname，音频格式取 URL 路径扩展名，避免查询参数导致误识别。

保存静音音量 0、关闭的系统音量镜像与音质偏好。修复预览模式间接枚举设备、触发镜像或媒体键逻辑的问题。

### 构建与诊断

`build.sh` 从 SwiftPM 查询实际二进制目录，先在临时目录组装并验证签名与 plist，再更新 `dist/净听.app`。按用户后续要求，默认备份旧版并保留数据安装到 `/Applications/净听.app`；保留现有稳定签名身份的选择逻辑。截图脚本也不再假定 `.build/debug` 路径。

新增 `apitest resolve <链接/BV/ID>`，只解析来源，不下载或播放。命令异常现在以非零退出码结束。

## 后续修复：点击播放输出杂音

真实设备查询显示 DTC 480 的物理格式为 Int16 / 2 声道 / 每帧 4 字节，虚拟格式为 Float32 / 2 声道 / 每帧 8 字节。原实现按物理格式解码，却用 Float32 环形缓冲与实时处理读写，导致解码端读越界、输出端帧数翻倍及写越界；日志出现大量异常采样。CoreAudio 的 [虚拟格式才是 IOProc 进行 IO 事务使用的格式](https://developer.apple.com/documentation/coreaudio/audiohardwarestream/virtualformat)。

修复后读取并验证虚拟格式，统一解码为交错 Float32，按回调布局输出；非交错缓冲使用 `UnsafeMutableAudioBufferListPointer` 逐声道访问，替代错误的 AudioBufferList 指针步进。软件音量对实际回调数据生效，不再因为物理设备是整数格式而失效。布局异常时保持静音，实时线程使用预分配缓冲，诊断采集改为音量后的实际输出数据。

另外将环形缓冲计数与退出标志改为 acquire/release 原子操作；seek 先停止 IO、串行操作解码文件与缓冲，停止时等待解码线程退出再释放资源。活动设备 ID 与用户新选目标分离，暂停恢复使用实际播放采样率，防止释放错误设备和恢复时格式错配。

验证记录在 `dist/verification/playback-fix/`：

- 完整测试 33 项通过，新增真实 PCM16 文件解码比对、交错/四声道非交错布局、软件衰减、零音量、缓冲不足、越界保护、异常值及十万帧并发环形缓冲验证。
- 地址消毒器下的 8 项 FloatPCMOutput 测试通过，未报告地址越界。
- Debug 版在 DTC 480 上使用生成的 PCM16 WAV 做零音量验证；Release 版使用实际缓存 FLAC 重复验证。两次均通过暂停/恢复、seek、连续重启、自然结束与原采样率/独占释放检查。
- 两次硬件验证均检测到有效非零解码数据，实际写给设备的音量后采样全为 0，异常采样数为 0；没有执行出声听感测试。

## 后续修复：解码器重插后输出混乱、自动播放与满音量

旧逻辑在固定设备消失时清除 UID 并递归切回自动模式，再按“已有当前曲目”重播；暂停、停止或下载中的曲目也会被重新启动。系统音量轮询只比较数字，无法区分新设备初始化的 100% 与用户调节；系统静音回退保存的音量也没有绑定原设备。

- 设备选择使用一次枚举快照，比较 ID 和 UID。手动固定的设备离线后保留 UID，不回退扬声器；自动模式优先外置输出并保留仍在线的当前解码器，避免独占导致默认输出变化后误切到其他设备。
- 监听设备列表、alive 与 data-source 事件；拔出/失效立即停止，插入防抖后只更新选择。监听器可注销，应用退出时释放。快速重插复用同一 ID/UID 也会让旧 IO 失效。
- 所有输出变化均取消解析、下载与歌词请求并释放旧引擎，保留队列/曲目/进度，等待用户点击播放。旧进度、状态和播完回调还需匹配播放代次，不能重启或覆盖新状态。歌单自动播放也需请求身份有效。
- 应用和引擎默认 10%；输出切换后最多 10%，保留静音或更低值。音量镜像比较设备 ID/UID，新路由/无效读数/自身静音恢复均重设基线。输出等待状态忽略系统音量，用户点击播放前也重设镜像基线。
- 系统静音改为设备会话：逐个保存原 mute 或各声道音量，只恢复所修改设备，UID 不符或设备消失则不写入；已静音的设备保留原静音。独占音乐的输出本身不施加系统硬件静音。

## 后续修复：进度正常但 DTC 480 无声

现场只读检测确认 DTC 480 的主硬件 mute=1，应用音量约 10%，耳机声道硬件音量为 1。播放进度正常说明解码和 IO 消费仍运行，但硬件静音使输出不可听。先前的零软件音量验证不能发现这一状态。

- 播放器在获取独占前捕获所选设备的主/各声道 mute；起播和恢复 IO 前只解除该设备的硬件静音，不改硬件音量。暂停、停止或启动失败后，在仍持有独占时恢复原静音，再恢复采样率并归还设备；UID 不符时不向替换设备写入。
- 硬件控制增加回读确认；无法解除静音会明确报错，避免继续显示无声播放。修复 UInt32 静音值经 `map(Float.init)` 误选位模式初始化的问题，改用明确的数值转换。
- 新增 `hogtest verify-muted-gain`：先以软件音量 0 验证硬件解除/还原，再确保硬件静音后以软件增益 0.1 采集实际 IO，确认有效非零数据和幅度边界。全过程保留原设备 mute 和硬件音量，测试不用于听感确认。

## 渐隐边界与边播放边下载（2026-10-27）

列表顶部按渐隐区高度增加滚动内容的上边距，首项在到顶时恰好位于完整不透明区；滚动后内容仍可进入顶部渐隐区。深浅色截图覆盖歌单、曲目、B 站收藏夹及内页，另核对带缓存进度和缓冲提示的完整播放页。

播放默认不再等待 `Downloader.ensureLocal` 完整返回。`RemoteAudioFile` 使用直连/系统代理偏好的 URLSession 将响应持续写入临时磁盘文件，区间表记录已到达的数据；后台解码读取缺失区间时等待数据，远处读取优先发送有界 Range，并严格核对 206、Content-Range 和 ETag。服务器不支持 Range 时回到顺序等待。只有响应完整结束、字节长度匹配时才原子发布完整缓存；取消和失败不将半截数据伪装成缓存。旧缓存名称及登录数据保持兼容，清理缓存时跳过正在写入的临时文件。

`PreparedAudio` 在后台探测并跳转，普通文件经 AudioFile 读取回调和 ExtAudioFile 解码；FLAC DASH 根据 sidx 和片段头映射为虚拟原生 FLAC，按需读取原始压缩帧。AAC DASH 单独按 moof/trun 取包并使用系统 AudioConverter 解码，避免系统 M4A 文件读取器在起播前扫描整份分段文件。既有 Float32 环形缓冲、独占输出和音量安全规则保留，实时回调没有网络访问或等待；缺数据时保持静音且进度不前移，恢复数据后淡入。解码失败显示错误，不作为正常曲终跳到下一首。

暂停时保留缓冲及下载；拖动在后台重新定位，共用当前下载源。设备断开仍暂停并等手动播放，重新出现后可以从同一个下载源重建解码，不依赖已完成的缓存文件。新曲目、退出或网易云登出取消旧源及阻塞读取。B 站先解析当前分 P，其他分 P 到播放时才取地址，减少起播请求和签名地址过期。

验证记录在 `dist/verification/progressive-playback/`：普通套件 71 项通过，4 项外部条件测试默认跳过；限速本机 HTTP 测试验证未下完整即可解码、远端 Range 跳转、取消唤醒、缓存完整发布与离线复用，以及错误页/截断响应拒绝；另覆盖取消期间的元数据读取唤醒。解码文件句柄集中管理，初始化失败和正常析构均可幂等关闭，回调上下文保留到文件关闭后。AAC 回归使用本机生成正弦信号并由系统 afconvert 编码，构造两个分段进行提前解码测试，不使用第三方解码依赖。
